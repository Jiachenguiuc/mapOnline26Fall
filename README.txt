在线交互地图项目说明与 AI 交接文档
更新日期：2026-11-04

一、项目目标
使用 GitHub Pages 托管一个可通过浏览器访问的在线交互地图，展示用户提供的 GIS 数据。
主要采用 HTML、CSS、JavaScript、Leaflet 和 GeoJSON 完成地图及界面功能。
当前已完成可本地运行的首版地图；尚未发布至 GitHub Pages。

二、技术路线
1. HTML：页面结构、地图容器、图层控制与信息展示区域。
2. CSS：地图及控件样式，适配桌面和移动端屏幕。
3. JavaScript：加载数据、初始化地图、处理交互和错误提示。
4. Leaflet：地图展示、缩放平移、GeoJSON 图层、弹窗和图层控制。
5. GeoJSON：保存道路/步道线要素和研究区域边界等空间数据。
6. GitHub Pages：发布静态页面。第一阶段无需后端、数据库或构建工具。
7. 用户已指定暂用 OpenStreetMap 底图；Leaflet 1.9.4 通过 unpkg CDN 引入，
   使用官方提供的完整性校验值。保留可见的 OpenStreetMap 版权署名。
   瓦片遵循浏览器默认缓存，仅按视口请求，无离线下载或批量预取。
   参考：https://operations.osmfoundation.org/policies/tiles/
   Leaflet：https://leafletjs.com/download.html

三、分工
用户负责：提供与更新 GIS 数据；解释字段含义；确认功能及界面效果；
          完成 GitHub 账户中必要的授权、仓库访问和发布设置。
AI 负责：生成和维护项目代码；实现地图交互；设计界面样式；准备部署配置；
         检查数据与路径问题；记录测试结果、已知问题和下一步工作。
不得把尚未完成的授权、发布或界面确认记录为已完成。

五、当前数据检查结果
检查时间：2026-11-01。以下为当前文件内容的检查结果，数据更新后需重新检查。

data/roadSurvey.geojson
- FeatureCollection，共 23 个要素，均为 LineString，未发现空 geometry。
- 主要字段：OBJECTID、Trail_Name、Trail_Type、Surface_Type、Date_and_time。
- 另含 GNSS 精度字段、GlobalID、Shape__Length 等属性。
- 可考虑以 Trail_Name、Trail_Type、Surface_Type 作为弹窗和筛选依据。
- 长度字段的单位和时间字段的时区/含义尚未确认，不应直接假定或标注。

data/LeeFJacksonBoundary.geojson
- 最新文件为 FeatureCollection，共 6 个 Polygon 要素，已包含坐标。
- 已在浏览器确认 6 个面边界绘制成功，支持图层开关与属性弹窗。
- 主要字段：OBJECTID、Acct、RecAcs、Preserve、Parcel_Num、Location、Owner、
  Shape__Length、Shape__Area。部分文本字段为空白。
- 未确认面积和长度字段的单位，不应直接用于统计展示。

数据约定：GeoJSON 使用 WGS84 经纬度，经度在前、纬度在后。
后续需检查坐标范围、几何有效性、空值、字段类型与数据体积。
保留用户原始数据；发现问题时先记录，不擅自补造边界或改写测量结果。

六、功能需求与实现顺序
已确定的总体要求：静态在线交互地图；采用上述技术栈；由用户确认界面效果。
以下为建议的首版功能，具体交互细节在开发时与用户确认：
1. 显示底图，支持缩放和平移。
2. 加载步道数据；有效边界数据补齐后加载边界。
3. 自动缩放至有效数据范围，提供返回全图的操作。
4. 提供图层开关、图例和比例尺。
5. 点击步道显示名称、类型和路面材质等信息；缺失字段友好显示。
6. 提供清晰的加载状态、数据加载失败提示和移动端布局。

可选扩展（尚未确定，不视为已承诺需求）：
- 按名称搜索，按步道类型或路面材质筛选。
- 分类配色、悬停高亮、信息侧栏、底图切换。
- 定位、统计摘要或数据下载；是否开放及如何展示由用户确定。

七、开发与部署约定
- 页面与数据使用相对路径，例如 ./data/roadSurvey.geojson，兼容 GitHub
  Pages 项目站点的仓库子路径；文件名大小写必须与磁盘上的文件完全一致。
- 开发时通过本地 HTTP 服务访问，避免直接双击 HTML 导致 fetch 加载失败。
- 推荐先采用仓库分支根目录发布；是否改用 GitHub Actions 在实际需要时决定。
- 仓库地址、默认分支、自定义域名、最终网址和 Pages 发布方式均待确定。
- 不把访问令牌、账户凭据或其他秘密写入前端代码、数据或仓库。
- GeoJSON 属性进入页面或弹窗时安全处理，避免将属性值直接作为可信 HTML。
- GitHub Pages 上的前端资源和数据会提供给访问者，发布前由用户确认可公开范围。

八、验收要点
实现后应检查：

- 缩放、平移、图层开关和弹窗工作正常，图例与实际样式一致。
- 缺失属性、空几何及加载失败时仍可使用页面并看到明确提示。
- 桌面和手机尺寸下地图与控件可用，底图版权信息可见。
- 发布后通过真实 GitHub Pages 地址复核资源路径和地图交互。
